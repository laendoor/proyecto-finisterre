## Sesión: fini-academika-claude-tooling

## Resumen

Sesión dedicada íntegramente al setup de tooling de desarrollo antes de arrancar Fase 1. Se
generalizaron skills existentes (`start-ticket`, `whats-next`), se crearon dos skills nuevos de code
review (`self-review`, `review-fix`), se rediseñó el flujo de `fini-status`/`fini-bitacora` para que
STATUS.md sea la fuente de verdad sin requests en tiempo real a GitHub, y se creó `fini-commit` como
skill autoinvocable que conoce la estructura de los 3 repos. Se documentaron las decisiones de workflow
en ADR-005.

### Workspace / configuración

- **`start-ticket`** (global) generalizado — quitadas todas las referencias a proyectos anteriores,
  ejemplos agnósticos, plan vive en la conversación salvo que se pida persistirlo.
- **`whats-next`** (global) generalizado — agrega issues unassigned además de `@me`, ordena por

- **`self-review`** (global) creado — lanza un Agent (context fork real) con el diff del PR; presenta

  los aprobados y pushea.
- **`fini-status`** actualizado — simplificado para leer solo STATUS.md sin requests a GitHub en
  tiempo real; mantiene `contexto-sesion.md` como fuente para la sección "Última sesión".
- **`fini-bitacora`** actualizado — agrega paso de sincronización con `gh` al cierre para actualizar
  la sección "Tickets — Académika" en STATUS.md.
- **`fini-commit`** creado — skill autoinvocable que conoce la estructura de los 3 repos (seminario
  local, proyecto-finisterre con remote, academika con remote); corre `git status` en paralelo y
  propone commits contextuales.
- **STATUS.md** actualizado — nueva sección "Tickets — Académika" y decisiones de sesión registradas.

## Decisiones tomadas

- **[ADR-005]** Workflow de desarrollo y estructura del repositorio — monorepo `api/` + `ui/`, PRs
  para features, CI como principal punto de calidad.
- **GitHub MCP descartado** — ya probado previamente, resultó verboso; `gh` CLI cubre todo lo
  necesario.
- **STATUS.md como fuente de verdad** — `fini-status` no hace requests a GitHub en tiempo real;
  `fini-bitacora` los hace al cierre y actualiza STATUS.md.
- **Hooks adicionales descartados** — `fini-bitacora` + CI cubren los casos de calidad sin overhead.
- **`self-review` y `review-fix` en global** (`~/.claude/skills/`) — útiles en cualquier proyecto, no
  específicos de Finisterre.
- **`fini-commit` en proyecto** (`.claude/skills/`) — hardcodea la estructura de los 3 repos,
  específico de este workspace.
- **Skills globales sin versionar** — se deja así por ahora, sin repo de dotfiles.
