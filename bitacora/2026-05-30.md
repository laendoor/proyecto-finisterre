### academika

**Branch creado:** `feature/auth-login-6`

**Commit `bf53298` — refactor(models): renombrar tablas a plural + extraer study_plans_courses**

El ticket #6 iba a introducir un modelo `User`. Al discutir el nombre de la tabla, surgió la pregunta "¿por qué no `users`?" que reveló que todas las tablas existentes usaban singular. Se decidió cambiar la convención a plural ahora, mientras el proyecto es chico y sin datos reales en producción.

Cambios del commit:

- Todas las tablas de entidades renombradas a plural: `degrees`, `courses`, `students`, `study_plans`, `course_enrollments`, `course_prerequisites`, `lkp_enrollment_types`
- Excepción acordada: `lkp_academic_status` y `lkp_enrollment_status` conservan singular (`statuses` suena forzado)
- Tabla de asociación M2M renombrada a `study_plans_courses` y extraída a `api/app/models/study_plans_courses.py` (estaba embebida en `study_plan.py`)
- Migración Alembic `e22a6112a67a` con `op.rename_table()` para cada tabla (upgrade + downgrade)
- ForeignKeys actualizadas en todos los modelos
- Imports actualizados en services, routers y tests
- Typing de `conftest.py` corregido: fixtures con `yield` anotadas como `AsyncGenerator[T]` en lugar de `T`
- `assert is not None` agregado en test que accedía a `.first()` sin type-guard (pre-existing)
- 62 unit tests + 38 integration tests verdes

**Plan acordado para ticket #6** (8 fases + Final):

- Beta: modelo `User` + migración (`users`, roles admin/director)
- Gamma: deps (`PyJWT`, `bcrypt`, `resend`) + config + auth utilities (password hashing, JWT)
- Delta: `AuthService` (login, refresh, forgot/reset password) + errores 401/403
- Epsilon: router `/api/v1/auth` + FastAPI dependencies (get_current_user, require_role)
- Zeta: integration tests de auth
- Eta: Frontend — login page + Server Actions + middleware Next.js (httpOnly cookies)
- Theta: Frontend — forgot-password + reset-password
- Final: pre-push + alembic check + push + PR

**Decisión clave de arquitectura frontend:** JWT almacenado en httpOnly cookies vía Next.js Server Actions (no localStorage). JS del cliente nunca toca el token. Protección estructural contra XSS.
