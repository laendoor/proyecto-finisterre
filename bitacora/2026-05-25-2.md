**Refactor estructural del módulo importer:**

**Decisión de diseño — HOF `parse_csv` vs context manager:**

- Evaluadas tres estrategias para DRY del patrón repetido (open + reader + skip header + for + try/except): context manager, generator, HOF
- El CM no puede manejar excepciones por fila: su `__exit__` captura excepciones que salen del bloque `with` completo; para skip-and-continue por fila, el try/except debe estar _dentro_ del loop
- HOF es la única estrategia que elimina completamente el loop + try/except de cada parser
- Implementado con type parameters de Python 3.12: `def parse_csv[T](path, parse_row)`

**Renombres a inglés:**

- `InscripcionRow → EnrollmentRow`
- `parse_inscripciones → parse_enrollments`
- `parse_datos_personales → parse_students`
- `parse_alumnos_guarani → parse_enrollment_history`
- `legajo → unq_id` en `Student` model, migración, `StudentRow`, tests, `FORMAT.md`
  - Motivación: el legajo es un ID de la UNQ sin equivalente en inglés; `unq_id` diferencia claramente de `doc_id` (DNI nacional)
  - La migración se editó directamente (no nueva migración): estamos en desarrollo y hay un único `schema_inicial`

- Separación deliberada: fixtures para tests automáticos rápidos, sample-data para pruebas end-to-end futuras desde make/script
