## Trabajo realizado

### academika

**Decisión de diseño — dónde va la lógica de DB del importer:**

Tres opciones evaluadas:
- A) Agregar métodos `upsert_from_rows()` al `StudentService` existente — acoplamiento cruzado entre capas
- B) Crear `GuaraniImporterService` dedicado sin heredar `BaseService` — frontera clara
- C) Mantener upsert en `importers/guarani/upsert.py` — rompe la convención de services

Opción B elegida: el importer es un caso de uso ETL distinto al CRUD; tiene sentido un service propio con la misma interfaz de DI (`__init__` + `dep()`).

**`Student.enrolled_at` — campo faltante:**

`StudentRow` tenía `enrolled_at` (fecha de ingreso a la carrera) pero el modelo `Student` no. Detectado al analizar el schema de upsert. Agregado al modelo + migración regenerada (`fc6f97d5203a` reemplaza `d0d14a4f408a`).

**`api/app/services/guarani_importer.py`:**

- `GuaraniImporterService`: DI vía `__init__(session)` + `dep()` classmethod (mismo patrón que `BaseService`, sin heredarlo)
- `import_students(path)`: orquesta `parse_students(path)` → `_upsert_students(rows)`
- `_upsert_students(rows)`: prefetch degrees + study_plans como dicts, upsert por `doc_id` via `INSERT ... ON CONFLICT DO UPDATE`, skip con warning si degree no encontrado, commit al final
- Returns `tuple[int, int]` (upserted, skipped)
- `_fetch_degrees()` y `_fetch_study_plans()`: helpers privados de prefetch

**`api/tests/unit/factories.py`:**

Builders compartidos para unit tests, extraídos del test file para reutilización futura (Fase Zeta integration tests):
- `make_student_row(doc_id, degree_code, plan_year) -> StudentRow`
- `make_degree(code) -> MagicMock`
- `make_study_plan(degree_id, year) -> MagicMock`

**`api/tests/unit/services/test_guarani_importer.py`:**

6 tests mockeando `_fetch_degrees` y `_fetch_study_plans` directamente (más limpio que mockear la cadena SQLAlchemy):
- `test_skips_when_degree_not_found`
- `test_upserts_when_degree_found`
- `test_commits_at_end`
- `test_mixed_rows_correct_counts`
- `test_plan_id_none_when_study_plan_not_found`
- `test_plan_id_set_when_study_plan_found`

25/25 unit tests verdes, `make check` limpio.

### Workspace / configuración

**VS Code ruff:**

- Problema: extensión `charliermarsh.ruff` instalada pero sin warnings ni format-on-save
- Causa raíz: `ruff.path` con `${workspaceFolder}` no resolvía correctamente; Python extension no tenía intérprete seleccionado
- Solución: rutas absolutas en `ruff.path` + `ruff.nativeServer: "on"` + selección manual del intérprete via "Python: Select Interpreter" (one-time per workspace)
- Configurado en `seminario/.vscode/settings.json` y `academika/.vscode/settings.json`
