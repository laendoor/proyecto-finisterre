## Decisiones tomadas

- **Patrón `action/FormData` (React 19)**: migración de `FormEvent` a `action` en todas las páginas de auth. El handler recibe `FormData` directamente, sin `e.preventDefault()` ni `new FormData(e.currentTarget)`.
- **Flujo register → login → workspace via middleware**: el route handler de register setea cookies (auto-login), la page redirige a `/login`, el middleware detecta la sesión y redirige a `/workspace`. Responsabilidades separadas — la página de register no necesita saber de `/workspace`.
- **Dos campos de password en /register**: `password` + `confirm_password`, validación client-side antes de llamar a la API. Pensado para el usuario, no para seguridad.
- **Fase final de tickets con UI = "Verificación y cierre"**: incluye tabla de casos de uso para validación manual + push + PR. Formalizado en skill `fini-ticket`.
